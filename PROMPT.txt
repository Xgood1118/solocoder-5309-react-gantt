用 React + Vite 写一个简易甘特图组件，能嵌入到项目里用。

主视图：横向是时间轴（默认按天刻度，可切换周/月），纵向是任务行（每行一个任务条）。任务条的颜色根据状态变化（未开始灰色、进行中蓝色、已完成绿色、已延期红色、已暂停黄色）。时间轴的今天位置有一条红色竖线标记。

任务条交互：
- 拖动任务条左右移动改起止日期
- 拖动任务条右边缘改结束日期
- 拖动任务条左边缘改开始日期
- 双击任务条打开编辑弹窗（改名称、负责人、进度百分比、子任务）
- 鼠标悬停任务条显示 tooltip（起止日期、工期、进度、子任务完成情况）

依赖关系：用户可以给两个任务之间画箭头连线（A 完成后才能开始 B），连线用 SVG 画，折线或者贝塞尔曲线都行。循环依赖要禁止（提示"存在循环依赖无法保存"）。被依赖的任务延期了，依赖它的任务自动延期（起日期跟着推迟）。

关键路径：在所有任务里找一条最长的链路（不考虑资源），把这条链路上的任务条描红加粗显示。如果用户改了某个任务的工期，关键路径要重算。

里程碑：特殊任务类型，菱形标记，零工期，只有一个日期点（通常是项目关键节点）。

筛选和分组：
- 按负责人筛选（显示某人的所有任务）
- 按状态筛选
- 按父任务分组（多级任务折叠展开）
- 当前视图能缩放到指定日期范围（自定义显示从哪天到哪天）

导出：当前甘特图能导出为 PNG（用 html2canvas 或者自己 SVG 转 canvas 的方式）和 JSON（数据备份），导入 JSON 还原。

数据存 localStorage 或浏览器内存（不用数据库），但支持多项目切换（一个项目对应一份数据）。

至少 3 个文件：甘特图主组件、任务条组件、依赖连线组件、日期工具函数分开。日期处理用 date-fns 或 dayjs 那种轻量库，不要 moment。

实际生产中会遇到这些场景：时间轴刻度切换：日/周/月/年。任务条悬停显示工期（按天计算，包含起止两天）。里程碑（零工期任务）用菱形标记，与普通任务条视觉上区分。依赖关系类型：FS（完成-开始）、SS（开始-开始）、FF（完成-完成）、SF（开始-完成）。关键路径上的任务用深红色边框标记。导出 PDF（带 SVG 矢量图）。缩放范围限制（不能缩到看不见）。多选任务批量修改属性。任务分组（按父任务）显示。日期拖拽时的吸附（按天对齐）。

补段用户场景：项目经理管一个 6 个月的研发项目，甘特图横跨 26 周。每个任务条对应一个开发任务（比如"用户登录模块开发" 5 天工期），有依赖关系（A 完成后才能开始 B），有里程碑（"内测发布"在第 12 周）。他每周一更新甘特图——勾掉完成的任务（标绿色），改延期任务的起止日期（系统自动算关键路径重算），给新需求加卡片。

依赖关系的细节：FS（完成-开始）最常见，A 完成后 B 才能开始。SS（开始-开始）A 开始后 B 立即开始（并行）。FF（完成-完成）A 完成后 B 立即完成（这种很少用）。SF（开始-完成）A 开始时 B 必须完成（这种也少）。循环依赖禁止（A 依赖 B，B 依赖 A 报错）。

里程碑是零工期任务，菱形标记，显示在对应日期的线上。关键路径上的任务用深红色边框，鼠标悬停提示"关键路径任务，延期会导致项目延期 X 天"。导出 PDF 用 SVG 转 Canvas（保证矢量清晰度）。

甘特图的核心是时间轴渲染，要支持日/周/月三种粒度切换，切换时左侧任务列表保持滚动位置不变。任务条按开始结束时间定位到精确的像素位置，鼠标悬停弹出任务详情卡片。拖拽任务条左右边缘调整起止时间，拖拽中间区域平移整段，拖拽到其他任务的区间时给红色边框提示冲突。

依赖关系用箭头表示（前导后续关系），FS/FF/SF/SS 四种依赖类型要可区分。拖拽建立依赖时高亮所有可连接的源任务/目标任务。依赖箭头用 SVG path 绘制，路径要避开任务条边缘，箭头头部要正对目标任务的开始/结束位置。

关键路径计算：按任务依赖关系找出最长路径，关键路径上的任务条用红色高亮普通任务用蓝色。里程碑（0 时长节点）用菱形表示。基线对比：保存一份基线数据并排显示，实际进度和基线偏差超过阈值时任务条变橙色。

实际工作流里还会有这些场景。一个项目从立项到收尾要走过"草稿-规划中-执行中-已暂停-已完成-已归档"六个状态，外加"已取消"作为异常终态。"草稿"是 PM 刚把项目建好还没拆任务的状态，这个状态下能自由改项目名/起止日期/成员。"规划中"是把任务拆好但还没正式开始——这个状态可以保存基线（基线 1），保存后基线数据冻结不能再改。"执行中"是项目正式开始，任务条按计划跑，进度百分比可以更新。"已暂停"是临时中断（资金不到位/客户要改需求），这个状态所有任务冻结不能改起止日期但能改备注。"已完成"是所有任务 100% 完成、里程碑全部达成，自动归档触发。"已归档"项目不再出现在主列表，移到归档库。状态之间不是任意切换的——"已完成"不能回到"执行中"（要新建一个 V2 项目），"已取消"是单向终态不可恢复。

多角色视图：项目经理（PM）有完整权限——能建项目、加成员、起基线、改任意任务、调整关键路径。开发成员能看到分配给自己的任务和自己所在小组的任务（看不到其他组的细节，任务名只显示概要），能更新自己负责的进度但不能改起止日期（要 PM 改），能在自己的任务上写评论。设计师角色类似开发但能上传设计稿附件。客户（外部访客）只能看"客户视图"——只显示项目名、整体进度百分比、关键里程碑日期、当前状态，看不到具体任务名/负责人/工期这些内部细节。审计员（公司 PMO/财务）只读全部数据，能看历史修改记录和基线对比，但写不了任何字段。角色之间通过"权限矩阵"控制——比如开发能评论但不能改工期，PM 能改工期但不能改项目的财务字段（金额/工时成本这些只有财务角色能看）。

时间与配额：免费版单项目最多 50 个任务、20 个依赖关系，超出提示升级。订阅版无限制。基线每 30 天能保存一次（防止乱存基线），同一天多次保存取最后一次。每个任务有"预计工期"和"实际工期"两个字段——实际工期超过预计工期 1.5 倍自动标"已延期"红色，超过 2 倍标"严重延期"加感叹号。任务进度更新有时间戳——PM 能看到"任务 X 在 Y 时刻从 30% 改到 45%"，连同改的人的昵称。循环任务（重复会议这种）有"下次发生"字段——超过下次发生时间没勾完成自动变橙色"逾期"。

数据一致性与级联：删除一个父任务时，所有子任务按策略处理——"级联删除"（子任务连同依赖关系一起删）、"升级为顶级任务"（保留子任务但解除父子，子任务的父 ID 置空）、"转移到回收站"（30 天后真删，期间能恢复）。改任务的"开始日期"时，所有依赖它的下游任务自动按依赖类型重算开始日期（FS 跟着推后、SS 跟着推后、FF 跟着推后、SF 反推上游）；改"工期"时关键路径自动重算。改任务的"负责人"时，被改人的工作量统计实时更新（看到自己本周新接了 X 工时的活）。多端协作（PM 在桌面端、开发在移动端、设计师在另一台电脑同时编辑）通过 storage 事件 + 版本号（每条任务带 version 字段）解决冲突——并发改同一任务时后改的提示"该任务版本已更新到 v3，请刷新"。导入项目 JSON 时检测项目 ID 是否冲突、依赖关系是否能完整还原（缺失的依赖任务标"孤立依赖"红色警告），版本号校验同上。导出时除了任务数据还要带"基线快照"和"评论快照"，导出的文件能被其他甘特图工具（比如 MS Project 简版）部分还原（依赖关系和工期保真，附件和评论可能丢失提示用户）。
